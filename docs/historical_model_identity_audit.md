# Historical Model Identity Audit

## Conclusion

The model that generated the 94,522 archived historical screening labels is **unresolved**. Three retained sources disagree:

| Evidence source | Reported screening alias | Evidence |
|---|---|---|
| Historical screening script | `gpt-4.1-mini` | `previous/empirical_evaluation/scripts/02_screening.py`, line 76 |
| Historical empirical README | `gpt-4o-mini` | `previous/empirical_evaluation/README.md`, line 10 |
| Unsuccessful manuscript | `gpt-4o` | uploaded `main.pdf`, Section 4.5.1 |

The archived screened CSV files contain title, year, DOI, abstract, source, case identifier, and `llm_decision`. They contain no requested model, returned model, request identifier, timestamp, prompt hash, or system fingerprint. No screening call log was transferred.

The 20 screened CSV files are timestamped 14–15 June 2026. The script first entered the reachable Git history on 21 June 2026, six days after those outputs were written. Every reachable Git revision declares `gpt-4.1-mini`, but that establishes the committed code state, not the configuration used for the earlier execution.

## Evidential rule

No current paper or report may state that the historical screening labels were generated by `gpt-4o`, `gpt-4o-mini`, or `gpt-4.1-mini`. The defensible description is:

> Historical zero-shot LLM screening labels were retained for 94,522 records, but the generating model alias cannot be established because the manuscript, repository README, and committed script disagree and no per-call provenance was saved.

This conflict is itself a concrete provenance consequence. It prevents model-specific interpretation of every historical screening label and demonstrates why executable code alone is insufficient when outputs predate the committed implementation and calls lack immutable configuration records.

## Extraction and evaluator aliases

The historical extraction script, evaluator script, and manuscript agree on the declared alias `gpt-4o-mini`. However, the extracted CSVs also lack per-call returned model identifiers and system fingerprints. The alias is therefore a consistent declaration, not a verified versioned execution identity.
